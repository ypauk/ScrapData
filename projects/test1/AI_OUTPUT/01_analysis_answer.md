1. Краткое описание задачи

Клиент хочет получить скрейпер интернет-магазина Professionele-Koeling.nl, который собирает данные о товарах из категории koelkasten-kisten.html.

На текущем этапе требуется не полный scrape, а тестовая выгрузка только 2 товаров. Для каждого товара необходимо собрать строго заданные поля из DS-PRK-Scraper.json, причем порядок и названия полей должны сохраняться без изменений. 
GitHub

В дальнейшем предполагается возможность обработки всего каталога, но сейчас объем теста явно ограничен двумя товарами.

Ключевые требования:

результат — JSON;

каждое поле — отдельное поле объекта;

не смешивать несколько характеристик в одну колонку/поле;

изображения нужно скачивать, а не только сохранять URL;

HTML описания не нужен — нужен чистый текст;

отсутствующие характеристики пока оставлять пустыми;

если скидки нет — Sale price должен быть пустым;

товары без наличия также должны включаться;

порядок полей должен строго соответствовать спецификации. 
GitHub

Уровень уверенности: высокий.

2. Какой конечный результат нужен

Основной результат:

JSON с 2 товарами для тестовой выгрузки.

Структура должна строго соответствовать DS-PRK-Scraper.json:

URL

Breadcrumb

Title

Short description

imageurl

image_name

Price

Sale price

Description

Specs

Spec_detail

Важно: пробелы в названиях вроде Title и Description являются частью предоставленной спецификации и не должны самостоятельно исправляться или переименовываться. 
GitHub

imageurl и image_name при наличии нескольких изображений должны содержать соответствующие значения через запятую.

Specs должен содержать характеристики, а Spec_detail — пары характеристик, где текст до : является названием характеристики.

3. Как лучше решить задачу
Рекомендация: PlaywrightEngine + парсинг HTML через DOM

Это наиболее подходящий вариант для данного проекта.

В предоставленных материалах прямо указано, что сайт работает на JS, API не найден, а scraper.py получает готовый PlaywrightEngine. Поэтому использовать Playwright как базовый механизм доступа к страницам — наиболее естественное решение. 
GitHub

При этом не следует усложнять scraping дополнительными технологиями.

Оптимальная схема на уровне подхода:

PlaywrightEngine → category page → product URLs → product pages → DOM extraction → JSON + скачивание изображений

Почему именно так:

категория уже содержит ссылки на товары;

pagination обычная, через параметр p;

данные товара находятся в HTML DOM;

структура сайта похожа на классический Magento-магазин;

для теста нужно всего 2 товара;

нет подтвержденной необходимости в отдельном API;

не требуется база данных;

не требуется Selenium;

не требуется отдельный Scrapy-пайплайн.

Текущий сайт также показывает обычную товарную пагинацию: например, категория отображает товары и ссылки вида ?p=2, ?p=3 и т. д. 
Professionele Koeling

Важное упрощение

Для текущего теста не нужно обходить весь каталог.

Достаточно:

открыть категорию;

получить ссылки товаров;

выбрать первые 2 требуемых товара;

открыть страницы товаров;

извлечь все необходимые поля;

скачать изображения;

сформировать JSON.

Это соответствует текущему требованию клиента: сначала проверить работу на двух товарах.

Для некоторых полей карточки категории достаточно. Например, на странице категории видны название, URL товара, изображение и цены.

7. Возможные сложности
1. Cloudflare

Самый существенный технический риск.

cf_clearance присутствует в предоставленных cookies, поэтому повторное выполнение scrape без актуального browser context может вести себя иначе. 
GitHub

Риск: средний.

2. Различия между category и product page

Некоторые поля есть только на странице товара.

Например, предоставленная product page содержит:

breadcrumb;

title;

short description;

обычную цену;

sale price. 
GitHub

Следовательно, нельзя надежно заполнить весь JSON только из category listing.

3. Формат характеристик

Spec_detail требует особой обработки:

всё до : — header.

Но конкретный HTML блока характеристик в предоставленном сокращенном product-page.html отсутствует.

Поэтому точный DOM-селектор и способ извлечения всех Spec_detail пока нельзя подтвердить на основании предоставленного HTML.

Это один из немногих действительно важных информационных пробелов.

4. Изображения

Необходимо не просто получить URL, но и скачать изображения.

Нужно учитывать:

несколько изображений;

абсолютные/относительные URL;

корректное имя файла;

возможные повторяющиеся имена.

10. План разработки
Этап 1 — Проверка доступа к категории

Цель: убедиться, что PlaywrightEngine стабильно открывает категорию.

Результат: получена рабочая category page.

Зависимости: существующий PlaywrightEngine.

Этап 2 — Получение 2 product URLs

Цель: извлечь ссылки на товары из карточек категории.

Результат: два корректных URL товаров.

Зависимости: этап 1.

Этап 3 — Получение страниц товаров

Цель: открыть product pages и получить полный DOM.

Результат: HTML двух товарных страниц.

Зависимости: product URLs.

Этап 4 — Извлечение полей

Цель: заполнить строго заданные поля DS-PRK-Scraper.json.

Результат: два объекта с правильными названиями и порядком полей.

Зависимости: DOM product pages.

Этап 5 — Обработка изображений

Цель: получить URLs изображений и сохранить сами файлы.

Результат: локальные изображения + соответствующие imageurl / image_name.

Зависимости: product page.

Этап 6 — Формирование тестового JSON

Цель: сформировать итоговый JSON только для 2 товаров.

Результат: тестовый output.

Зависимости: этапы 1–5.

Этап 7 — Валидация

Цель: проверить соответствие результата спецификации.

Проверяется:

все обязательные поля;

порядок;

названия;

пустые значения;

цены;

изображения;

чистый текст описания;

отсутствие HTML;

количество товаров = 2.

Результат: готовый тестовый файл для отправки клиенту.

Этап 8 — После одобрения теста

Цель: масштабировать тот же подход на весь каталог.

Результат: полноценный scrape.

Зависимость: подтверждение клиентом тестового JSON.

12. Можно ли решить проще

Да.

Самое простое решение — не строить полноценную сложную scraping-систему.

Не нужны:

отдельная БД;

Scrapy;

Selenium;

API abstraction layer;

сложная архитектура;

распределенный scraping;

очередь задач;

Docker;

отдельная система хранения.

Использовать существующий PlaywrightEngine, открыть category page, собрать product URLs, открыть product pages, извлечь нужные поля и сформировать JSON.

Более того, для тестовых 2 товаров даже pagination пока не нужна.

При переходе к полноценному scrape pagination уже потребуется, но она стандартная и явно представлена ссылками ?p=2, ?p=3 и т. д. 
GitHub

Есть также потенциально более простый вариант — парсить только category pages, но он не подходит для полного требования, поскольку category HTML не содержит всех нужных полей. Поэтому переход на product pages является оправданным минимумом.
